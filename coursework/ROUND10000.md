## 实际方案和命令

原第 5000 步 `last.pth` 是完整训练恢复状态；第 4500 步 `best.pth` 是继承的验证最佳候选。
使用完整状态续训，不能把只加载 best 权重并重建 Adam 称为完整恢复。
短预检比较两个入口的真实 6→7 更新，要求参数、Adam、scheduler、RNG、裁剪、噪声、损失和验证逐位一致。
正式续训第一个 5000→5001 更新后立即保存状态，便于核验实际启动。
第一次选用了更早入口的试跑状态，来源检查拒绝了加载，未进入新入口的梯度更新；日志保留在 `resume_preflight.log`。
改用与 5000 步入口一致的第 6 步状态后，`resume_preflight_v2` 已退出 0，`resume_verification.json` 记录逐位一致结果。

在容器项目根目录执行，复现时把输出改成未存在的新目录：

```bash

export CUDA_DEVICE_ORDER=PCI_BUS_ID
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4

  --manifest runs/lab244_10000_20261009/data/train_val.json \

```

## 查看进度

本地项目根目录可执行：

```bash
python3 -m coursework.monitor_training --run runs/lab244_10000_20261009
python3 -m coursework.remote244 \
  'tail -5 runs/lab244_10000_20261009/logs/finetune_10000.log'
```

`monitor_training` 是只读操作，返回实际 Python 进程、最新更新、GPU 进程、显存、首个恢复 checkpoint 和退出状态。
有 PID 或日志不代表已经完成；有 COMPLETE 也须核对 `summary.json` 的实际 completed_steps 和 stop_reason。

## 文件位置

- `logs/finetune_10000.log`、`.pid`、`.exit`：训练与完成审计后台日志及退出码。
- `finetune/last.pth`：第 10000 步完整恢复状态；`best.pth`：验证选中的第 10000 步推理权重。
- `finetune/train.csv`、`validation.csv`、`config.json`：全部历史、新更新、验证和来源契约。
- `finetune/summary.json`、`COMPLETE`、`training_audit.json`：结束后的真实步数、停止原因及审计。
- `resume_verification.json`、`logs/resume_preflight_v2.*`：真实更新恢复一致性预检。
- `startup_verification.json`、`continuation_lock.json`：启动证据、预算、原权重与来源哈希。
- `data/`：训练/选择和新旧测试清单、预处理与哈希。
- `environment.json`、`server-preflight.txt`：本次环境版本、服务器、挂载、空间与 GPU 检查。
